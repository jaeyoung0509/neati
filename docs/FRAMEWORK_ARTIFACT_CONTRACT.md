# Framework artifact removal contract

Developer Artifacts recognizes the default SvelteKit `.svelte-kit` and Next.js
`.next` stores inside a selected workspace. It reports bytes before deciding
whether a unit can be removed. All project artifacts remain unselected initially
and separate from Cleanup's ready-cache total.

## Recorded whole-output variants

| Unit | Positive contract | Other contents |
| --- | --- | --- |
| `.svelte-kit` | Direct, exact `@sveltejs/kit: 2.37.1` declaration; default output resolution; the recorded sync-only root-route type variant; only verified `types`, generated `tsconfig.json`, `ambient.d.ts` and `non-ambient.d.ts` entries | Build/client/server/service-worker output, environment/route variants whose complete declarations do not match, authored additions and unknown entries keep the whole parent observed |
| `.next` | Direct, exact `next: 15.5.14` declaration; default output resolution; only verified uncompressed Webpack-v1 cache trees, optionally the exact generated `{"type":"commonjs"}` package marker | `BUILD_ID`, server, standalone, static, fetch/image/offline caches and unknown entries keep the whole parent observed |

These are deliberately narrow format contracts, not a claim of support for every
output generated by those framework versions. The manifest establishes a direct
dependency declaration; neati does not execute a package manager or infer an
installed compiler version. Ranged, aliased, conflicting or other versions do
not authorize a whole parent. An existing independently verified generated child
can remain reviewable when its parent is observed.

SvelteKit documents its [generated default directory and configurable output
root](https://svelte.dev/docs/kit/project-structure#Other-files-svelte-kit).
Next.js documents [default `.next` and custom `distDir`
resolution](https://nextjs.org/docs/app/api-reference/config/next-config-js/distDir).
Neither directory name establishes authored-content or current-use safety.

## Inert configuration and custom discovery

Project manifest reads are bounded to 256 KiB; the unique-key JSON parser
accepts at most 64 KiB for either manifest or configuration. All metadata must
be regular UTF-8 files. Inspection refuses links and concurrent identity changes.
Unique-key JSON, depth and collection limits prevent ambiguous metadata.
Configuration is never imported or evaluated.

The whole-output resolver accepts only an absent configuration or the supported
loader's fixed export of an inert JSON object with default output options. It
checks package module mode and configuration precedence. When Next has no
direct loader configuration, a bounded 32-level ancestor search must establish
configuration absence all the way to the filesystem root. Presence, unreadable
metadata or an exhausted search leave the parent advisory; ancestor code is
never read or run. Imports, functions, spreads, duplicate keys, TypeScript,
multiple configuration files, custom options and unknown loader syntax leave
the parent advisory.

A bounded relative custom `outDir`/`distDir` string may be shown as an observation.
A literal in dynamic JavaScript is only a hint, never its evaluated result.
Absolute paths, parent traversal, ambiguous separators and selector syntax are
not followed. The ordinary discovery walker still descends unknown/default/custom
wrappers to find independently evidenced nested projects. No custom path gains
removal authority.

## Fresh authorization and recoverable movement

Preparation binds a private one-shot plan to the current inventory and exact
registered relative unit. It rechecks the selected workspace/project identity,
manifest/config identity and content fingerprint, generated format, original Git
index namespace and ownership completeness. A whole parent and its child cannot
coexist in one plan. Measurement alone cannot override authored, tracked, nested
repository, linked, deployment or credential protection.

macOS use checks cover the entire project, including open files, working
directories and held build locks. Active, failed, timed-out or incomplete checks
block framework removal; there is no unknown-use consent override for these
generated units. Discovery, planning and execution obtain fresh observations.
Overlapping project scopes are measured sequentially to prevent sibling
inspection descriptors or Git subprocesses from contaminating a project-use
probe. Independent groups still use the shared scan pool, capped at four
workers. This scheduling does not relax the use verdict or ignore other owners.
Windows/Linux observations do not imply an implemented use/removal adapter.

Execution holds no-follow descriptors, stages the exact accepted directory and
checks the original Git namespace, complete generated tree, project use and
metadata again immediately before the Trash port. Only the probe's exact owned
PID/inspection descriptors may be excluded from a complete lsof field stream.
Other handles, warnings, malformed output or output limits cannot establish idle.
Changed evidence restores the accepted staged unit when its original name is
available; substitutions never reach Trash. Timestamp restoration does not
restore authority because inode, change time and held-tree fingerprints remain
bound.

Moving to Trash is recoverable movement, not measured free-space recovery.
Preview and result bytes refer to the selected exact unit. After a successful
move, the UI removes overlapping parent/child observations and requests a fresh
scan before reviewing their remaining scope. Expiry updates belong only to the
visible mounted review. Exact paths, evidence and rebuild consequences stay in
keyboard-accessible disclosures.
